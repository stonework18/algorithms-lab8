## Контрольные вопросы

Вот ответы на контрольные вопросы по теме «Двоичный поиск. Хеш-таблицы» без привязки к коду.

1. **Условие для применения двоичного поиска**  
   Массив должен быть отсортирован (обычно по возрастанию) и поддерживать произвольный доступ к элементам за O(1) (например, обычный массив или вектор). Если данные не отсортированы, двоичный поиск неприменим.

2. **Сложность двоичного поиска и почему она логарифмическая**  
   Временная сложность — O(log n). На каждом шаге интервал поиска сокращается вдвое, поэтому количество шагов пропорционально логарифму числа элементов по основанию 2. Например, для миллиона элементов достаточно около 20 сравнений.

3. **Разница между итеративной и рекурсивной реализацией**  
   Итеративная использует цикл и требует O(1) дополнительной памяти. Рекурсивная использует стек вызовов, поэтому глубина рекурсии O(log n) и дополнительная память O(log n). По времени обе реализации работают за O(log n), но рекурсивная может быть медленнее из-за накладных расходов на вызовы.

4. **Опасность `mid = (left + right) / 2`**  
   При больших значениях `left` и `right` может произойти целочисленное переполнение (выход за диапазон типа). Правильно вычислять середину как `mid = left + (right - left) / 2`.

5. **Что такое хеш-таблица и её компоненты**  
   Хеш-таблица — это структура данных для хранения пар «ключ–значение», обеспечивающая быстрый доступ. Основные компоненты: массив бакетов (ячеек), хеш-функция, преобразующая ключ в индекс, и механизм разрешения коллизий.

6. **Требования к хеш-функции**  
   - Детерминированность: один и тот же ключ всегда даёт один и тот же хеш.  
   - Равномерное распределение: ключи должны равномерно заполнять таблицу.  
   - Быстрое вычисление.  
   - Желательно использовать все биты ключа и учитывать размер таблицы.

7. **Коллизия и способы борьбы с ней**  
   Коллизия — ситуация, когда разные ключи дают одинаковый хеш. Способы разрешения: метод цепочек (хранение списка элементов в одном бакете) и открытая адресация (поиск другой свободной ячейки по определённому правилу: линейное/квадратичное пробирование, двойное хеширование).

8. **Отличие метода цепочек от открытой адресации**  
   В методе цепочек коллизии разрешаются путём хранения нескольких элементов в одном бакете (например, в связном списке). В открытой адресации все элементы хранятся непосредственно в массиве, и при занятости ячейки происходит поиск следующей свободной по некоторой последовательности.

9. **Первичная и вторичная кластеризация**  
   Первичная кластеризация возникает при линейном пробировании: занятые ячейки образуют длинные непрерывные последовательности, что увеличивает время поиска. Вторичная кластеризация — при квадратичном пробировании: также образуются группы, но менее выраженные.

10. **Средняя и худшая сложность операций в хеш-таблице**  
    Средняя сложность вставки, поиска и удаления — O(1) при хорошей хеш-функции и низком коэффициенте загрузки. Худшая — O(n), когда все ключи попадают в одну цепочку или при открытой адресации с крайне неудачным распределением.

11. **Когда эффективнее двоичный поиск, а когда хеш-таблица**  
    Двоичный поиск лучше, когда данные статичны (редко изменяются), уже отсортированы, и нет необходимости в дополнительной памяти. Хеш-таблица эффективнее для динамических наборов с частыми вставками, удалениями и поиском, когда важна средняя скорость O(1).

12. **Коэффициент загрузки и его важность**  
    Коэффициент загрузки — отношение числа элементов к размеру таблицы (n/m). При его росте увеличивается вероятность коллизий и время операций. Обычно поддерживают значение не выше 0.7–0.75, после чего выполняют рехеширование.

13. **Рехеширование (динамическое расширение)**  
    Создаётся новая таблица увеличенного размера (часто в 2 раза), все существующие элементы пересчитываются по хеш-функции и вставляются в новую таблицу. Это позволяет снизить коэффициент загрузки и сохранить эффективность операций.

14. **Выбор размера хеш-таблицы и почему простое число**  
    Размер выбирают достаточно большим, чтобы коэффициент загрузки был низким. Часто берут простое число, чтобы уменьшить кластеризацию и обеспечить более равномерное распределение при использовании хеш-функции вида `key % size` (особенно для целых ключей).

15. **Хеш-функция для строк**  
    Распространён полиномиальный хеш: `h = (h * p + c) % m`, где `p` — небольшое простое число (например, 31 или 37), `c` — код очередного символа, `m` — размер таблицы. Такой подход быстро вычисляется и даёт хорошее распределение для строк.
